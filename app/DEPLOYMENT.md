# LIFE RPG — самостоятельный backend

## Архитектура

- Frontend: React + Vite.
- API: Hono + tRPC.
- Database: MySQL через Drizzle.
- Auth: анонимный профиль, подписанная HttpOnly cookie-сессия.
- Recovery: случайный код восстановления; в MySQL хранится только SHA-256-хеш.
- AI: Groq через OpenAI-compatible AI SDK. Ключ существует только на сервере.

GitHub Pages подходит только для статического frontend и не запускает Hono или MySQL. Для этой версии нужен Node.js-хостинг, который запускает `npm start`, и отдельная MySQL-база. Frontend и API должны открываться с одного origin (или нужно отдельно настроить CORS и cookie-политику).

## Переменные окружения

Скопировать `.env.example` в `.env` и задать:

- `APP_SECRET` — длинная случайная строка для подписи сессий (не менее 32 случайных байт).
- `DATABASE_URL` — MySQL connection string.
- `GROQ_API_KEY` — секретный API-ключ Groq.
- `GROQ_MODEL` — модель, доступная вашему Groq-аккаунту.
- `GROQ_BASE_URL` — обычно `https://api.groq.com/openai/v1`.

Не задавать эти значения через `VITE_`-переменные: они попадут в браузерный bundle.

## Первое развёртывание

1. Создать MySQL database.
2. Выполнить `npm ci`.
3. Применить миграцию `db/migrations/0001_anonymous_recovery.sql` к существующей таблице `users` (или добавить колонку `recoveryCodeHash varchar(64) NULL` в схему до первого создания таблиц).
4. Выполнить `npm run build`.
5. Запустить `npm start`.
6. Проверить `POST /api/auth/bootstrap`, затем `GET /api/trpc/auth.me`.
7. Настроить `GROQ_API_KEY` и выбрать модель из списка, доступного аккаунту.

## Важные ограничения

- Потеря одновременно устройства и кода восстановления означает потерю доступа к анонимному аккаунту.
- Код восстановления даёт полный доступ к прогрессу. Его нельзя публиковать или отправлять посторонним.
- Перед публичным запуском нужно добавить распределённый rate limiting на `/api/auth/bootstrap`, `/api/auth/recover` и `/api/auth/recovery-code`. Встроенная cookie-политика использует `SameSite=Lax`; frontend и API должны оставаться на одном origin.
- В текущей реализации recovery-код многоразовый, чтобы можно было подключить несколько устройств. Создание нового кода заменяет предыдущий.
- Облачная синхронизация использует существующую таблицу `game_saves`; конфликт разрешается по revision и `updatedAt`. Для интенсивного одновременного использования нескольких устройств потребуется транзакционная проверка ревизии.
